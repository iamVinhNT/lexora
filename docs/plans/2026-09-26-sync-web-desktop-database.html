Mục tiêu
Thống nhất cơ sở dữ liệu SQLite giữa Web backend và Desktop app vào vị trí chung ~/.lexora/data/lexora.db (được giải quyết qua sharedDatabasePath()). Tự động kích hoạt cơ chế migrate/merge các database cũ (legacy) khi chạy lần đầu, đảm bảo tính toàn vẹn dữ liệu và hỗ trợ đa tiến trình an toàn bằng SQLite WAL mode.
Phân loại Lane
Strict. Lý do: Thay đổi vị trí database mặc định, cơ chế data migration từ các database legacy và đồng thời truy cập từ nhiều tiến trình (Web server & Desktop app).
Kiến trúc
Sử dụng apps/backend/src/db/shared-database.ts để quản lý đường dẫn chung và migration dữ liệu từ các đường dẫn cũ. Backend và Desktop cùng trỏ về sharedDatabasePath() và gọi prepareSharedDatabase() khi khởi chạy.
Stack
Node.js, TypeScript, better-sqlite3, Fastify, Electron, Vitest.
Tiêu chí nghiệm thu
AC-1 (Export sharedDatabasePath và prepareSharedDatabase từ @lexora/backend), AC-2 (Web backend mặc định dùng DB chung và tự động migrate legacy DB khi khởi động), AC-3 (Desktop app mặc định dùng DB chung và tự động migrate legacy DB khi khởi động), AC-4 (Bảo toàn khả năng override qua DATABASE_PATH cho test môi trường độc lập), AC-5 (Tất cả test backend và desktop pass 100%).
Rủi ro
RISK-1: Tranh chấp quyền truy cập hoặc ghi đè file DB giữa web và desktop (được bảo vệ bởi SQLite WAL mode và link nguyên tử trong prepareSharedDatabase); RISK-2: Gãy các test phụ thuộc vào đường dẫn mặc định cũ (cập nhật test assertions chính xác).
Ràng buộc bất biến
  • Không xóa dữ liệu gốc của người dùng khi migrate; giữ nguyên file legacy để rollback an toàn nếu cần.
  • Luôn giữ nguyên chế độ WAL (journal_mode = WAL) và ràng buộc khóa ngoại (foreign_keys = ON).
  • Cho phép ghi đè đường dẫn database qua biến môi trường DATABASE_PATH hoặc tham số test.
  • Giữ cấu trúc code ngắn gọn, không thêm abstractions thừa (Ponytail level full).
Thứ tự thực hiện: Task 1 (Backend shared-database & server) → Task 2 (Desktop paths & server) → Task 3 (Quality Gates & Verifier).
#Nhiệm vụTiến độ

Task 1: Cấu hình export shared-database và tích hợp vào Web Backend

Files
  • Chỉnh sửa: apps/backend/package.json
  • Chỉnh sửa: apps/backend/src/server.ts
  • Chỉnh sửa: apps/backend/tests/server.test.ts
Interfaces
  • package.json: Thêm export ./shared-database hoặc ./db/shared-database để desktop và consumers có thể import.
  • server.ts: Hàm parseDatabasePath(value) trả về sharedDatabasePath() khi value === undefined. Hàm startServer() gọi await prepareSharedDatabase(databasePath) trước khi buildApp() nếu databasePath !== ':memory:'.
  • server.test.ts: Cập nhật assertion kiểm tra giá trị mặc định của parseDatabasePath(undefined) khớp với sharedDatabasePath().
Traceability
  • Acceptance: AC-1, AC-2, AC-4.
  • Risks: RISK-2.
  • Evidence: Chạy vitest trên apps/backend/tests/server.test.ts và apps/backend/tests/db/shared-database.test.ts đều PASS.

Task 2: Tích hợp shared-database vào Desktop App

Files
  • Chỉnh sửa: apps/desktop/src/paths.ts
  • Chỉnh sửa: apps/desktop/src/desktop-server.ts
  • Chỉnh sửa: apps/desktop/tests/paths.test.ts
  • Chỉnh sửa: apps/desktop/tests/desktop-server.test.ts
Interfaces
  • paths.ts: resolveDesktopPaths(userDataPath, resourcesPath, options?) trả về databasePath: options?.databasePath ?? sharedDatabasePath(options?.home).
  • desktop-server.ts: startDesktopServer() gọi await prepareSharedDatabase(options.databasePath) trước khi chuẩn bị lưu trữ và kết nối database.
  • paths.test.ts: Cập nhật kiểm thử để xác nhận đường dẫn DB trỏ tới shared path dưới thư mục home (ví dụ ~/.lexora/data/lexora.db).
Traceability
  • Acceptance: AC-3, AC-4, AC-5.
  • Risks: RISK-1, RISK-2.
  • Evidence: Chạy vitest trên apps/desktop/tests/paths.test.ts và apps/desktop/tests/desktop-server.test.ts đều PASS.
