Learn Active Recall Redesign Implementation Plan
0 / 0
Plan metadata & global constraints
Goal
Replace immediate five-step repetition with persisted delayed-recall groups, objective two-attempt scoring, exact resume, and atomic idempotent completion.
Lane
Strict. Database migration, public API, concurrent state, backup contract, scoring, and major UI direction change.
Architecture
Pure domain rules own grouping, cursor, output evaluation, and scoring. Fastify service/repository own transitions and atomic persistence. React Query renders server-owned cursor; frontend never infers authoritative progression.
Tech Stack
TypeScript, Fastify, SQLite, Drizzle ORM, Zod, React 18, React Query 5, TailwindCSS, Vitest, Testing Library, Playwright runtime verification.
Spec
docs/specs/2026-09-17-learn-active-recall-redesign.md
Acceptance
AC-1 through AC-26 from approved spec.
Risks
RISK-1 migration drift; RISK-2 backup incompatibility; RISK-3 duplicate effects; RISK-4 legacy ambiguity; RISK-5 analytics shift; RISK-6 N+1; RISK-7 mobile keyboard; RISK-8 hint leakage.
Non-goals
No AI integration, speech scoring, SM-2 replacement, gamification, rich text, new UI/runtime dependency, or unrelated module redesign.
Global Constraints
  • TDD: each behavioral production change follows failing test, observed RED, minimal GREEN, regression run.
  • Preserve REST envelope and downward route → service → repository → DB dependency flow.
  • Every new file needs repository-standard @file/@description header.
  • Keep knowledge state one-directional and one level per qualifying update.
  • Preserve unrelated dirty files; leave changes unstaged unless user explicitly requests commit.
  • Backup v1 remains restorable; export emits v2 only after migration.
  • Use existing dependencies and design tokens. No new package.
Execution order: Task 1 → Task 2 → Task 3 → Task 4 → Task 5 → Task 6 → Task 7 → Task 8. Tasks share API/schema files, so implementation remains sequential in current workspace. Strict reviewer and verifier run after implementation.
